# Desktop support for bravebot 0.9.0

## Plan and interaction design

1. Complete approval cards. Put checker status and explanation beside existing output/path approvals. Add a separate one-time content approval showing source, expected contents and the complete content. Explain that checking already sent bytes to the backend, while approval releases them to the planner; never infer approval from a verdict. Show processor remarks above write diffs with an untrusted label and omitted-line count. Preserve cancellation, background-session routing and request-kind matching.
2. Add a Watches dialog to each conversation. Show path, state and expiry, an add-file form, Stop per watch and Stop all. Watches exist only while the conversation is open in this app; closing the app stops them. Reuse upstream watch policy and polling, cap at eight/seven days, defer automatic turns while busy and identify their source in the transcript. Cancellation stops automatic continuation. Do not ingest file contents into a generated prompt.
3. Add an Agent settings dialog accessible without a conversation. Its sections are Connection, Hooks and Run settings. Connection reports the bundled agent's configuration, setup routes, network environment and administrator-managed values without exposing credentials. Hooks use explicit program/argument fields, lifecycle selection and optional tool filtering, with validation and an explicit Save action. Existing hook failures remain visible as turn notices. Run settings selects a native JSON file, shows the selected path and precedence, and applies to future turns/model discovery without editing source files.
4. Improve turn status. Use stable failure categories with actionable descriptions and preserve cancellation as its own outcome. Show context as not measured, measured or unavailable, independent of accumulated billing tokens.
5. Verify incrementally: Rust protocol/refusal/lifecycle/config tests; Node state and configuration tests; TypeScript and build; isolated Electron acceptance covering new controls and background/cancellation behavior. Finish with workspace tests, Clippy, upstream locked suite and existing deterministic Electron checks.

## Visual design

Use the existing modal, transcript-card, disclosure and button patterns. Approval evidence stays inline next to the decision. Routine diagnostics and automation management live in labelled dialogs rather than enlarging the transcript toolbar with individual controls. Verdicts use text plus color, never color alone. Failures and loading states are explicit, form labels are associated with controls, Escape closes dialogs and focus returns to the invoking control. Narrow layouts stack forms and allow evidence to scroll without hiding decision controls.

  processor writes, and keyboard/narrow-layout checks. CI now runs it under Xvfb.

  evidence and settings at desktop and narrow widths.

conversation-workflow drivers. The integration checks use isolated profiles and fixture
services; paid-provider and packaged-app runs are separate deployment checks.
