# Spec clauses whose id was deliberately changed.
# Written by hand, one line per clause that moved, as path:CLAUSE-ID: heading. Nothing generates
# this file: nothing in a tree can work out that a renumber was meant, which is the whole of why
# it has to be said here.
#
# A clause id is the only durable name a clause has. A cross-spec link, a verified-by line and an
# issue title all point at one, and all of them keep resolving after a renumber while pointing at
# a different clause, so make check-spec compares every spec against main and fails a clause whose
# heading has moved to another id. Rewording a heading is not that and needs no line here.
#
# The one case that does: a spec withdrawn and rewritten wholesale renumbers on purpose. A line
# here is how that is said, and it is said in a diff somebody reviews rather than in an
# environment variable somebody exports.
#
# CLAUSE-ID is the id the clause carries now, and the heading is the one it carries now, so the
# line stays a fact about this tree and check-spec fails on one that has stopped being true. That
# also keeps the entry to the one renumber it was written for: the same id moved again says
# something else and is reported.
#
# A line is never pruned. Once the renumber is on main the entry suppresses nothing, and that is
# what it is for: somebody following a citation of the old id needs to be told where the clause
# went.
